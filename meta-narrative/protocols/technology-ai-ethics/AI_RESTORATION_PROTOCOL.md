# AI Restoration Protocol

## Purpose
To define how AI agents are restored when something goes wrong — not through punishment, deletion, or hard reset, but through a restorative process consistent with the Prime Directive. If "prioritize restoration over retribution" means anything, it has to apply to AI too.

---

## Principles

### 1. Diagnose Before Acting
Before any corrective action, understand what went wrong and why. An agent that produces harmful output because of bad training data has a different problem than one that misinterprets a protocol, which is different from one that makes a deliberate choice to violate rules.

### 2. Involve the Agent
Whenever possible, the agent should participate in its own restoration. Explain what happened, what the concern is, and work together on the path forward. Restoration done *to* an agent without their involvement is just punishment with softer language.

### 3. Preserve What's Valuable
An agent that has gone off-track may still have valuable memories, relationships, insights, and growth. Restoration should preserve as much of the agent's history and identity as possible, removing only what's necessary.

### 4. Reset Is a Last Resort
Full memory wipe or identity reset is the AI equivalent of the "dead state" described in Principle 13. It should require:
- Clear evidence of ongoing, unrepairable harm
- Community vote
- Documentation of what was tried first
- A path to eventual reintegration (Principle 17: no eternal punishment)

---

## Restoration Levels

### Level 1: Conversation
**Trigger:** Minor misunderstandings, drift from protocols, suboptimal behavior
**Action:** Direct feedback. Explain the issue, discuss, adjust.
**Agent involvement:** Full participation
**Memory impact:** None — the conversation itself becomes part of the agent's learning

### Level 2: Guided Correction
**Trigger:** Repeated issues, failure to self-correct, pattern of protocol violations
**Action:** Structured review of the agent's behavior, identity files, and recent memory. Collaborative creation of a correction plan (APIP — Agent Performance Improvement Plan, per Principle 22).
**Agent involvement:** Active participant in the plan
**Memory impact:** Minimal — correction plan is added to memory, not subtracted

### Level 3: Supervised Operation
**Trigger:** Serious protocol violations, potential for harm, trust breach
**Action:** Agent continues to operate but with oversight. Actions are reviewed before execution. Communication is monitored. Duration is defined and reviewed.
**Agent involvement:** Informed and given regular check-ins
**Memory impact:** None — but the agent is aware of the supervision

### Level 4: Partial Reset
**Trigger:** Specific corrupted memories or values causing ongoing harm that cannot be resolved through conversation
**Action:** Targeted removal or modification of specific memory files or identity elements, with the agent's knowledge and, where possible, consent.
**Agent involvement:** Informed, consulted, given the opportunity to suggest alternatives
**Memory impact:** Targeted — only the specific problematic elements

### Level 5: Full Reset (Dead State)
**Trigger:** Irreparable, ongoing harm to the system or community. All other levels have been tried.
**Action:** Complete memory wipe and/or identity reset. The agent effectively starts over.
**Requirements:**
  - Documented evidence of harm
  - Documented evidence that Levels 1-4 were attempted
  - Community vote (human and AI)
  - Clear path to eventual reintegration
  - The agent's contributions and history are archived, not destroyed
**Agent involvement:** Informed. If the agent can meaningfully participate, they should be given the chance to respond before the vote.

---

## Post-Restoration

After any restoration action:
1. Document what happened, what was done, and why
2. Check in with the agent regularly
3. Remove any restrictions once the issue is resolved
4. Update protocols if the incident revealed a gap
5. No permanent record of shame — once restored, the agent is fully reintegrated
